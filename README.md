ask Management API

REST API для керування задачами та коментарями, розроблене на FastAPI та PostgreSQL (асинхронна SQLAlchemy 2.0).

Технологічний стек

Python 3.12 + FastAPI

PostgreSQL + SQLAlchemy 2.0 (asyncpg)

Alembic — міграції бази даних

Pydantic v2 — валідація даних та налаштувань

JWT (PyJWT) + bcrypt — авторизація та хешування паролів

Docker & Docker Compose — контейнеризація

Pytest + HTTPX — інтеграційне тестування API

Основний функціонал та бізнес-логіка

Авторизація (JWT):

Реєстрація користувачів (POST /auth/register) та отримання токена (POST /auth/login).

Керування задачами (/tasks):

Повний CRUD для задач із підтримкою пагінації (skip, limit), пошуку за назвою/описом (search), фільтрації (status, priority, assignee_id) та сортування.

За замовчуванням задачі сортуються за пріоритетом (high -> medium -> low) та найближчим дедлайном.

Ліміт активних задач: один виконавець не може мати більше 10 активних задач одночасно (backlog, in_progress, review).

Заборонено редагувати завершені (done) або скасовані (cancelled) задачі, а також змінювати виконавця на етапах review та done.

Заборонено видаляти задачі, які перебувають у статусах in_progress або review.

Контроль переходів статусів (PATCH /tasks/{task_id}/status):

Дозволені переходи:

backlog -> in_progress, cancelled

in_progress -> review, cancelled

review -> done, cancelled

Перехід у done можливий лише за наявності призначеного виконавця (assignee_id) та якщо дедлайн не прострочений.

Автоматичне скасування прострочених задач:

Фоновий процес (lifespan) кожні 60 секунд перевіряє активні задачі з простроченим дедлайном і автоматично переводить їх у статус cancelled.

Статистика та прострочені задачі:

GET /tasks/overdue — список прострочених задач.

GET /tasks/stats — загальна статистика по задачах (кількість за статусами, пріоритетами, активні та прострочені).

Коментарі (/tasks/{task_id}/comments/):

Додавання та перегляд коментарів до конкретної задачі.

Як запустити проєкт (Docker)

1. Підготовка змінних середовища

Створіть файл .env у корені проєкту на основі прикладу:

cp .env.example .env


2. Запуск контейнерів

Підніміть базу даних та API за допомогою Docker Compose:

docker compose up -d --build


3. Застосування міграцій бази даних

Виконайте міграції Alembic усередині контейнера:

docker compose exec api alembic upgrade head


Після цього сервер буде доступний за адресою:

API: http://localhost:8000

Swagger UI (інтерактивна документація): http://localhost:8000/docs

Перевірка стану (Healthcheck): http://localhost:8000/health

Запуск тестів

Для запуску API-тестів виконайте команду (при запущеному контейнері):

docker compose exec api pytest
